# 字段和计算定义

## 档件

| 档件 | 字段（可用中文表头，顺序以档头为准） | 含义 |
|---|---|---|
| `catalog.json` | `version`, `longitude_deg`, `latitude_deg`, `sheets`, `edges`, `aliases` | 数据版本、局部基准、图框、成对图边、全批别名链 |
| `pixels.csv` | `sheet,name,u,v,note` | 图幅编号、观测点名、列行坐标 px、原始备注 |
| `ground.csv` | `sheet,name,crs,unit,x,y,note` | `WGS84` 的经度纬度或 `LOCAL-ENU` 的东坐标北坐标 |
| `witness.csv` | `edge,name,au,av,bu,bv,note` | 登记拼缝编号、见证点名、甲乙两侧独立像素坐标 |

`source` 保留文件名、起止物理行号和逐列原值。行号从 1 起算，跨行备注占多条物理行而只计一条记录。空文件、只有空行、只有表头分别为 `EMPTY_FILE`、`BLANK_FILE`、`HEADER_ONLY`。表头与空行另计。数值缺省符号集中定义，原字符串和数值 0 保留不同语义。CSV 整表采用同一编码，按 BOM 或 UTF-8／GB18030 识别。破坏后续列界的引号错误会拒收整档。

## 控制点

图幅编号保留前导零。像素 `u` 向右、`v` 向下，图框四边包含端点。名称先做全角和大小写归一，再沿已登记别名链取终点。以 `(图幅, 归并名)` 连接像素和地面记录。同组最大点间距不超过 0.001 px 或 0.001 m 时，最早的物理行进入配对。组内冲突则整组隔离，像素行也会记录地面冲突所涉及的行号。

`WGS84` 只接受 `deg`，经纬度依次为 `x`、`y`。先以零椭球高转 WGS84 地心坐标，再按基准经纬旋转至 ENU，输出 E、N 米。`LOCAL-ENU` 的 `m`、`cm` 分别直读和除以 100。WGS84 以 15 km 三维弦长设工作区，本地平面以同半径筛查。单位和值后缀矛盾时隔离，禁止以坐标大小推测系别。

对 `E=a·u+b·v+c`、`N=d·u+e·v+f` 做中心化与尺度归一的 SVD 最小二乘，导出还原后的六个系数、设计条件数及线性变换行列式。每幅最多 32 组，至少 3 个非共线。设计秩检查相对阈值为 `1e-8`，近奇异或最小尺度不超过 `1e-9 m/px` 的仿射不可用。

控制点残差是拟合坐标减实测坐标的平面长度。默认上限 0.75 m，等于阈值算通过，计算容差为 `1e-9 m`。当全点拟合有超限，遍历可用的三点假设，按同一阈值筛选并重复重估到成员不变。排除要求至少四点且超过半数支持；保留支持最多的唯一稳定集合。并列、共线或无法稳定时，给整幅阻断原因。离群记录保留两表原行和重估前后残差。

## 独立拼缝与签审

图边用像素框的北东南西边登记，双侧明示相接边及是否反序。每个见证点必须落在双方指定图边 0.5 px 内。见证名与同幅已登记控制点同名或同别名，或像素位置在控制点 0.05 px 内的记录隔离。见证同名、沿边距离在 0.05 px 内的重复记录成组隔离。每边最少三个独立站，两侧分别覆盖至少 60% 的边长，且次序与登记相符。

独立见证按两幅重估模型分别投影。向量取乙侧减甲侧，沿甲边正切方向及其逆时针法向分解，最大平面距离作验核判定。默认上限 1.50 m，计算容差为 `1e-9 m`。缺模型或次序不合则不可测，偏差为 `null`；覆盖不足或见证表有隔离行时允许保留实测偏差，禁止签成通过。

图幅只有拟合有效且登记的所有拼缝均通过时可签。任何已知超限为退修，缺模型或证据不足为暂缓。签审员名字为内部记录，首签版本固定为 1；同人重复请求返回签审原记录，其他人无法用旧版本覆写。不同批次的签审互相独立。

## 对账与运行清单

控制点原件＝采信＋离群＋隔离；地面点＝已配对＋隔离；见证点＝可用＋隔离。「可用」指行级证据通过检查，整条边还需模型、覆盖和次序。三张账均核对原件行号多重集。批次键由四份原件 SHA-256、参数和规则版本生成。SQLite 只提交验证完成的整份快照，证据包带输入摘要、创建时间、耗时和签审。

每个档件最多 1 MB，不接收在线上传。未模拟椭球高、其他基准转换或栅格重采样。页面默认保留当前操作会话，重开后可用相同参数取回原批次。签审属于单机档案记录，不提供身份认证或审批流。

## 规则迁移复核

旧批次指先前以另一规则版本留存的正式批次，来源可为库内 `runs`（`source_kind=run`）或 `sample_data/legacy/<id>.json` 归档（`source_kind=archive`）。复核沿用旧批次参数按现行规则重新解码、配对、拟合、重估与验缝，不写回原件，不改动原批次快照与签审。

每幅并列「旧结论」「新口径复算」与「对照」：状态和原因都相同为 `AGREE`，任一改变为 `CHANGED`，无法取得原件或旧结论缺失为 `UNVERIFIABLE`。原签审按 `CURRENT`／`STALE`／`INVALIDATED`／`ABSENT` 登记：现规则签审为 `CURRENT`；旧规签审在复算仍可签时为 `STALE`（须补签），复算已不可签时为 `INVALIDATED`；该幅原本无签审为 `ABSENT`。

「可重验依据」逐项列原件摘要、控制点源行、重估模型、拼缝见证、三表对账和原签审，每项标明取自旧证据（`archived`）还是新复算（`recomputed`）。「待补」单列：`SIGNATURE_STALE`、`UNSIGNED_AT_SOURCE`、`RECOMPUTATION_NOT_READY`、`EVIDENCE_NOT_RETAINED`（旧档无逐行依据，`missing` 给出缺项，`restored_by=recomputed` 表示已由复算补足依据）、`SOURCE_UNAVAILABLE`、`SOURCE_CHANGED`、`RECOMPUTE_FAILED`。

复核不允许产生正式批次：若同一原件与参数已有异规正式 `runs` 批次，`POST /api/review/runs` 返回 `409 RULE_MIGRATION_REQUIRED` 并指向复核接口。复核册存于独立 `rechecks` 表，`recheck_id` 由源标识、源规则版本、现行规则版本、原件摘要与参数生成，重复生成返回原册。复核结论不是签审记录，也不得回填到源批次的 `signatures`。
